# PathoScribe Portfolio Prototype v1.2 PDF 원고

이 원고는 `scripts/generate-portfolio-pdf.py`가 생성하는 `PathoScribe_Portfolio_v1.2.pdf`의 내용 기준이다. 제작자는 김선미이며, 실제 구현·검증된 범위만 기록한다. 전체 35건을 Gemini로 연속 실호출한 성능평가로 표현하지 않는다.

## 1. 표지

- 프로젝트명: PathoScribe
- 한 줄 설명: 육안 소견, 병리 결과, 위탁검사 결과의 입력·구조화·검수 과정에서 생성형 AI가 초안을 제안하고, 사용자가 원문 근거를 확인한 뒤 승인하도록 설계한 폐암 중심 교육용 웹서비스
- 제작자: 김선미 · 개인 프로젝트 · Portfolio v1.2
- URL: https://pathoscribe.vercel.app/
- 핵심 정의: 병리 진단을 대신하는 서비스가 아니라 전사·입력·검수 업무를 지원한다.

## 2. 제작 계기와 페인 포인트

- 자유서술 원문을 정형 필드로 옮기는 반복 입력과 의학용어·영문 표현의 오탈자 가능성
- 병리 결과문 안에 진단명, 크기, 절제연, 림프절, 병기, 면역·분자병리 정보가 혼재
- 기관마다 다른 위탁검사 결과지와 내부 의뢰정보의 수작업 대조
- 생성형 AI가 원문에 없는 값을 생성할 수 있는 위험

공개 자료와 교육용 가상 업무 흐름을 바탕으로 설계한 개인 프로젝트이며, 실제 환자 데이터나 실제 병원 내부 업무자료를 사용하지 않는다.

## 3. 실제 업무와 서비스 기능 연결

1. 육안 소견 입력·검수: 원문과 구조화 결과를 비교하고 숫자·단위·좌우·검체 수를 확인한다.
2. 병리 결과 구조화·검수: 원문 값을 자체 입력 템플릿에 배치하고 용어·누락·불일치를 확인한다.
3. 위탁검사 입력·매칭: 등록된 가상 PDF·이미지의 항목을 가상 내부 의뢰정보와 대조한다.

모든 업무는 원문, AI 추출값, ground truth, 담당자 확정값을 분리하며 사용자 확인 전 자동 확정하지 않는다.

## 4. 주요 사용자와 사용 흐름

- 주 사용자: 병리 전사 업무를 수행하는 보건의료정보관리사
- 병리의사: 원문 작성·판독 주체, 시제품에서는 검토 상태 조회
- 병리 검사 담당자: 검사·검체·블록 진행정보 제공 범위
- 품질관리자: 개인정보가 제거된 오류·누락·수정 현황 조회
- 흐름: 역할 선택 → 업무 선택 → 가상 사례 불러오기 → AI 구조화 → 원문 대조 → 담당자 확인

## 5. 육안 소견 전사·검수

저장된 교육용 오류 사례 `EVAL-GROSS-006`을 사용해 장기, 검체, 부위, 좌우, 크기, 개수, 절단면, 병변 위치, 블록 수를 원문 근거와 함께 비교한다. 검체의 좌측 표현과 병변 위치의 우측 표현이 충돌하는 경우처럼, 원문에서 충돌하거나 누락된 값은 확인 필요로 남긴다.

## 6. 병리 결과 구조화·의학용어 검수

검체, 장기, 부위, 수술, 조직학적 진단·유형, 종양 크기, 분화도, 절제연, 림프절, 면역·분자병리, 원문 pT·pN·pM을 자체 템플릿에 배치한다. `EVAL-PATH-015`의 면역병리 판정값 누락처럼 고위험 항목은 자동수정하지 않고 원문 확인을 요청한다. 낮은 위험의 철자 후보만 제시하며 좌우·병기·양성/음성·크기·절제연·림프절·유전자·면역표지자는 자동수정하지 않는다.

## 7. 위탁검사 결과 입력

교육용 가상 PDF 9개와 저화질 PNG 1개를 사용한다. `EVAL-OUT-004`의 의뢰번호 불일치처럼 의뢰번호, 검사명, 검체, 접수일, 보고일, 결과를 가상 내부 의뢰정보와 비교하며 담당자 확인 전 확정하지 않는다. 임의 파일 OCR 업로드는 구현하지 않았다.

## 8. 사용 데이터와 출처

- 국립암센터 폐암 임상 라이브러리 합성데이터: 원본 XLSX 15,000개 합성 레코드(훈련 10,000건, 테스트 5,000건), 업무 연결·평가사례의 구조화 원천
- 폐암 세부진단·면역병리·병기·기관지내시경 공개 API: 집계 참고와 입력 형식 보조
- 국가암지식정보센터 암정보사전: 3,544개 용어 검색과 로컬 용어 후보
- 폐암 레지스트리 메타정보: 253개 필드 정의
- 프로젝트 생성 가상 연결 데이터: 전체 9개 테이블 150,000행, 웹 미리보기 48건
- 프로젝트 생성 평가·문서 자료: 평가사례 35건, 위탁검사 PDF 9개·PNG 1개

공개 합성·집계·메타정보와 프로젝트 생성 가상자료를 실제 환자자료로 표현하지 않는다.

## 9. 생성형 AI와 사용자 승인

1. Gemini가 비정형 가상 원문에서 원문에 존재하는 값만 구조화한다.
2. 각 값에 evidenceText를 연결하고 원문에 없으면 null·not_found로 처리한다.
3. 날짜·숫자·단위·좌우·검사번호·검체명은 규칙으로 재검수한다.
4. 제안 적용·원문 유지·직접 수정·확인 필요 상태를 사용자가 결정하며 변경은 확정값에만 반영한다.

## 10. 평가 결과와 안전장치

- 정답 기준값(ground truth) 기반 고정 평가사례 35건 회귀검증: 정상 12건, 오류 포함 23건
- 오류 사례의 기대 경고 코드 24개 재현: 오류 사례 23건에 분포
- 실제 Gemini 대표 가상 사례 기본 동작 시험(smoke test): HTTP 200, mode=gemini, 스키마·evidenceText·not_found 확인
- 35건 전체 Gemini 연속 실호출 결과 파일은 등록되지 않았으므로 모델 성능 수치로 과장하지 않는다.
- HTTP 200은 Gemini API 연결과 구조화 응답 반환이 정상적으로 완료되었다는 뜻이며, 의료적 정확도를 증명하는 수치가 아니다.
- 실제 환자정보 입력 금지, 고정 caseId, 서버 전용 키, 요청 크기·호출 제한, 사용자 최종 확인
